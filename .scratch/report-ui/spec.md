# 报表 UI 批次（report-ui）spec

> Status: R1~R8 + 批 C/C2/D 已实现（2026-09-22~23）；**批 E 进行中（2026-09-24，spec 已定稿，待实现）**
> 决策时间：2026-09-22，需求来自用户六条想法，逐条已确认
> 实现顺序建议：R2 → R4 → R3 → R6 → R1 → R5 → R7（先删后加，纯前端收尾）

## 背景

当前报表（`templates/` + `src/report.py` + `templates/static/app.js|css`）只有折扣降序一种排序，
卡片详情排版松散，链接无图标。用户提出 6 条改进，本文档是定稿。

## 需求（用户确认版）

### R1 排序（组内）

- 维度三选一：**默认 = 折扣降序（现状）** / 价格升 / 好评率降。
- 好评率排序附带「好评数量范围筛选」chips：全部 / ≥500 / ≥5000，
  作用于**当前组**的显示集合；「详情待补」（无 reviews）的条目不参与好评率排序，固定排组尾。
- 排序范围：**只影响当前分组**，不跨组。
- 切换排序或筛选后，该组回到第 1 页。
- payload 需补数值字段 `price_int`（`reviews.score/count` 已在 payload）；
  前端不用 `price_text` 字符串排序。

### R2 删除 ITAD 链接

- 用户实测：`itad_url`（ITAD deal 链接）302 直跳 Steam 商店页，信息冗余 → **删除**。
- 卡片展开态去掉 ITAD 链接（`app.js buildCard` 的第三个链接）。
- `classify.SEEN_KEEP` 去掉 `itad_url`（新落库省 ~348KB/全量）；
  `classify.py` 里「itad_url 348KB 可砍」的旧注释更新为本决策。
- 旧 `state.json` 里已落的 `itad_url` 字段**留存不迁移**（下次该条目更新时自然消失）。

### R3 详情排布

- `card-detail` 中间加**竖向分隔线**，分左右两栏：
  - 左栏 = 价格类：Steam 史低 / 全周期最低 / 近一年最低；
  - 右栏 = 时间 + 比价：折扣开始 / 折扣结束 / 各比价行。
- 窄屏（≤ 断点 768px）回落单栏纵向堆叠。

### R4 链接前置 + SVG 图标

- Steam / 小黑盒链接移到 `card-summary` 的**价格区、折扣价之前**（横向小图标排布）。
- 图标用 **inline SVG 常量**内嵌 `app.js`（不下载 favicon 文件、不发外链请求）；
  链接保留文字 `aria-label`。ITAD 不再有链接（R2）。

### R5 密度切换（一行一条 / 一行两条）

- 页面级控件：**单列 / 双列**。手机端默认单列；PC 端可切双列（每行两张卡）。
- 选择存 `localStorage`，刷新保持。
- 双列时**每页条数不变**（不与断点分页逻辑耦合，避免「布局与每页条数错位」的老坑 §7.3）。

### R6 英文名显示

- payload 里 `title`（ITAD 英文名）已有，**零新增请求**。
- 规则：**PC + 单列** → 卡片标题旁灰色小字英文；
  **手机端 / 双列模式** → 只在详情展开里显示「原名」一行。
- fallback：若联动实现麻烦，全部放详情展开里（用户已许可）。

### R7 方向键翻页

- `←` / `→` 对「当前活动分组」翻页。
- 活动分组 = 最近一次被点击翻页按钮 / 卡片的分组；无记录时 = 第一个未折叠分组。
- 与现有按钮翻页共用 `pages` 状态；输入焦点在输入控件上时不响应（当前页面无输入框，防御性判断即可）。

### R8 封面图换小尺寸

- 现状：卡片缩略图用 `banner600`（回落 `banner400`/`boxart`），但缩略图只有几十像素宽，
  600px 大图加载慢（用户反馈）。
- 改法：`report.py` 的 payload `banner` 字段改为**优先 `boxart`**（ITAD assets 里的小尺寸），
  `banner600/400` 不再使用；`boxart` 缺失时保持现状回落（前端已有无图模式兜底）。

#### E1 ⭐ 史低判定改 Steam 口径（用户 Q6 = 方案 B）

**问题**：页面只做 Steam，但 `deal.flag` 的 N/H/S 是 **ITAD 全商店口径** ——
存在「Steam 首次到某价、别家更早更便宜过」的条目会被 ITAD 标成 H/S，而对 Steam 买家这是新史低。

**✅ 已澄清的关键事实（`tools/steam_flag_probe.py` 离线验证，零新增请求）**

- `storelow/v2` 响应 `lows[]` 本来就含 **price 和 timestamp**（§3.6 已实测
  「4.2 CNY @ 2025-09-18」），但 `itad.fetch_storelow` 只取了 timestamp ——
  **判定所需的数据已经在 fetch**。
- 该接口每天已在跑（200 个/批，日常 1~4 次请求）→ 本方案**不新增任何请求**、
  不改抓取流程、不改 state schema。
- 51 条交叉制表（`last_low_at` vs 折扣开始 `2026-09-24 01:18`）：

  | ITAD flag | 判定 | 与开始的间隔 |
  | --- | --- | --- |
  | N（9） | 全 = 新 | **全部 0.0h** |
  | H（33） | 全 = 平 | 37d ~ 2493d |
  | S（9） | 全 = 平 | 44d ~ 2100d |

- 窗口取 ±1h / ±6h / ±24h / ±72h **结果完全相同**（要么 0 小时、要么 ≥37 天）
  → 不需要调参，取 **24h** 只是给 ITAD 记录延迟留余量。

**⚠️ 如实说明**：今天的 51 条里，新旧口径**结果完全一致**，改口径不改变任何一条的分类。
它的价值是口径正确 + 覆盖未来那个真实存在的分歧场景。该分歧率（有多少 H/S 其实该算「新」）
未量化 —— 量化需单独约 10 次 ITAD 请求抽样全目录，**本批不做**。

**规则**（新增 `classify.steam_low_class`）：

```
low_kind(deal) is None       -> None       # 不是史低，不进报表（§4.1 原逻辑不变）
low_kind(deal) == "unknown"  -> "unknown"  # storeLow 缺失，如实标记（§10）
flag == "N"                  -> "new"      # 全网首次必定 Steam 首次，无需比时间
last_low_at 或 start 缺失     -> "tie"      # 取不到时间，回落 ITAD flag（H/S 都算平）
|last_low_at - start| <= 24h -> "new"      # Steam 店内史低就是这次创下的
否则                          -> "tie"      # Steam 以前到过这个价
```

**术语变更**：`新史低` = Steam 首次到达该价；`平史低` = Steam 以前到过该价
（**含 ITAD 的 H 与 S**）。**「店史低」退役** —— 本页全是 Steam 店史低，
用它会产生「那别家呢」的误读。

### 批 F3（2026-09-24 13:1x，用户截图：概览每框独占一行）

> 用户要求：**手机两行、电脑一行，不要双端同步，也不要写死**（还提到平板）。

**根因**：批 F2 用的 `grid-column: span 3 / span 2` 是**无效简写** ——
`grid-column` 简写里 start 的 span 会覆盖 line 值；当 end 也是 span 且使
start 变成 `span(count+1)` 时构成循环依赖，浏览器**直接丢弃整条声明**，
于是每个框退化成默认 1 格宽……在容器只有 3 列时就是每框独占一行（截图现象）。

**改法**（两档各自写死，不共用一套）：
- 手机 `@media (max-width:768px)`：`repeat(6, 1fr)`；
  第 1 排 `nth-child(-n+3)` 各 `span 2`（1/3），第 2 排 `nth-child(n+4)` 各 `span 3`（1/2）
  → 3 + 2 两行都铺满；`:has(> .stat-box:nth-child(6))` 时第 2 排改 `span 2` → 3 + 3
- 平板/电脑 `@media (min-width:769px)`：`repeat(5, 1fr)` 一行 5 个；
  `nth-child(6)` 设 `grid-column: 1 / -1` 跨满整行（罕见）
- 关键：一律用**单值** `grid-column: span N`，不再写 `span A / span B`

**这次改用了真机验证而不是推算**：`tools/measure_layout.js`（Edge headless + CDP，
Node 22 内置 WebSocket，零依赖）实测每个 `.stat-box` 的 boundingRect，按 top 分行。
22 种组合（11 个宽度 × 5/6 框）**全部通过**：

| 视口 | 5 框 | 6 框 |
| --- | --- | --- |
| 320~768px | 3 + 2 ✓ | 3 + 3 ✓ |
| 769~1440px | 5 ✓ | 5 + 1（跨满）✓ |
