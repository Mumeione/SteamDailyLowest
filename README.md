# SteamDailyLowest

每日抓取 Steam 折扣，筛出「当日新增的史低」游戏，生成手机友好的静态 HTML 报表。

**在线报表（GitHub Pages）：<https://mumeione.github.io/SteamDailyLowest/>**

## 它能看什么

- **当日新增史低**：只收本体游戏的史低，并按 **Steam 店内**口径分成 **新史低**（Steam 首次到这个价）
  与 **平史低**（Steam 以前到过）两档
- **好评分档**：好评达标（≥70% 且 ≥100 条评价）/ 高热度·口碑不一（评价数 ≥10000），冷门游戏不展示
- 每张卡片：封面、中文名（Steam `l=schinese`）、现价/原价、**剩 X 天**、史低档位、
  好评率与评价数、折扣力度条、Steam/小黑盒直达链接；
  展开可看**距上次史低多少天**（悬停/点按看具体日期）、折扣结束时间、乌克兰/印度区比价（±百分比）
- 页面目前只开放「**当日新增**」视图；`本周(14天) / 折扣中 / 即将过期` 的位置已留好，
  数据在后台攒着（**不做「已过期」**——过期折扣没有浏览价值）

## 筛选条件

报表里每一条都经过下面这些判定，**全部由 `config.json` 驱动，页面不再重复展示**：

| 条件 | 规则 |
| --- | --- |
| 游戏类型 | 只收本体游戏，不收 DLC / 合集 / 原声带 |
| 是否史低 | 只收 **Steam 店内史低**：**新史低** = Steam 首次到这个价（`storelow` 时间戳与本次折扣开始相差 ≤24h，或 ITAD 标记全网新史低）；**平史低** = Steam 以前到过这个价 |
| 商店范围 | 只看 Steam 一家，不参考其他平台的低价（ITAD 自带的 H/S 标记是全商店口径，仅作回落） |
| 好评达标分组 | 好评率 ≥ **70%** 且 评价数 ≥ **100**（`min_positive_ratio` / `min_review_count`） |
| 高热度分组 | 评价数 ≥ **10,000**（`notable_review_count`），**不看好评率**，单独折叠、默认收起 |
| 冷门过滤 | 评价数 < **100** 的游戏不展示（拿不到详情的进「详情待补」，不丢） |
| 绝对下限 | 可选 `absolute_min_positive_ratio`，设了就按它再砍一道；不设则不加此限制 |
| 多版本 | 同一 appid 出现多条时**只留价格最低的那条** |

阈值改动后，页面上的分组标题（`好评达标` 旁的门槛文字）会自动跟着变，改 `config.json` 即可；
**本表是手写文本，改阈值时需同步更新**。

## 运行方式

- GitHub Actions 每天自动运行（**05:14** 主跑 + **07:24** 补跑，15:14 预抓详情缓存），
  跑完自动发布到 Pages 并把状态库回写到 `data` 分支
- 数据源：[IsThereAnyDeal](https://docs.isthereanydeal.com/) 官方 API（Steam 官方 API 不提供历史价格）+ Steam 商店（中文名/比价）
- 状态（SQLite 之外用 JSON）增量攒库：好评率、appid、中文名、史低时间永久/TTL 缓存，逐轮补齐

## 本地运行

```bash
pip install requests jinja2
# config.json 放入 ITAD API key（已 gitignore，勿提交）
python run.py            # 全流程：抓取 → 报表 → output/index.html
python run.py --prefetch # 只补详情缓存，不出报表
```

> 区域价格与好评数据来自第三方，仅供参考；以 Steam 实际结算为准。
