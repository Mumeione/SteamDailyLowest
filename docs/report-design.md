# 报表设计

> 描述报表的当前实际形态（S9 UI 重做定稿）。
> ⚠️ 具体像素 / 变量值以 `templates/static/app.css` 为准；
> 视觉迭代的决策与实测过程记录在本地工作区（不入库），本文只写现状。

## 页面结构

```
index.html
├── .topbar（吸顶）：站点名（图标 + 双色分段）/ 导航 5 项 / 生成时间 / 手机汉堡按钮
├── #msgbar（顶部消息区，最多两行：节日条 + 提示/告警条）
├── main .wrap
│   ├── #filterbar：筛选按钮（带「已选 N 项」角标）+ 摘要行（今日新增：新史低 X · 平史低 Y）
│   ├── #home
│   │   ├── #picks：顶部大卡横排（‹ › 翻页，排名徽章）
│   │   └── #sections：四板块两列行列表
│   └── #listview（点导航后）：板块完整列表 + 滚动加载
├── #drawer + #drawer-mask：筛选面板（排序 / 日期 / 折扣区间 / 好评数量 / 史低类型）
├── .floaters：右下角浮动按钮（筛选 / 精简模式 / 返回顶部）
└── footer：链接 + 一句话说明 + 免责（居中）
about.html：抓取概览 / 史低构成 / 筛选口径 / 数据来源 / 汇率 / 每日更新日志 / 免责
```

- 导航 5 项 = **新史低 · 即将到期 · 热门游戏 · 大额折扣 · 全部折扣**；点站点名回首页。
  **四板块顺序**固定为「新史低 → 即将到期 → 热门游戏 → 大额折扣」（单列时按此复原）。
- **顶部消息区**（`#msgbar`）最多两行：① 节日条（季节主题色，服务端 `src/announcements.py`
  按北京时间筛）② 提示/告警条（**陈旧告警 >`stale_warn_hours` 黄 / >`stale_banner_hours` 红，
  优先于站点通知**）。两行都空则整块隐藏。
  内容源 `content/announcements.json`（手工维护，改内容不动代码）。
- **筛选**：`#filterbar` 一颗「筛选」按钮 + 摘要行；面板 `#drawer` 五维分组、
  **选项点击即生效**、角标只算偏离默认的项（排序不计入）；
  **板块隐含的无效选项 + 没有数据的天数一律置灰**。手机档「筛选」按钮搬进右下浮层。
  **日期默认「全部」**（2026-10-10）：板块与「全部折扣」页默认全量展示，不收窄窗口；
  已生效的日期限制（近 N 天/具体日）恒显示为已选标签，「全部」只在用户手动选过时
  显示，标签 ✕ = 恢复默认一步清掉。手机档「筛选」按钮搬进右下浮层。
- **列表**：滚动加载 —— 每批 `list_batch`（默认 30）条，**自动追加到 `list_auto_max`
  （默认 300）就停**，只留手动「继续加载」（防止「全部折扣」页几千条无限追加）；
  翻页 / 切板块后滚回列表顶部。

## 顶部大卡（「最值得买」）

- **池子**：折扣开始 ≤ `home_new_low_days`（7 天）· 还在折扣期内 · 史低类型 ∈ {新史低, 平史低}，
  **按顺序逐层取**（优先新史低，不够才补平史低）。
- **排序**：**大卡专属权重档 `PICKS_WEIGHTS`（与板块排序刻意拆开）** ——
  折扣 40 / 名气 25 / 口碑 15 / 间隔 10 / 紧迫 5 / 新鲜 5；
  前置门槛：有详情 · 好评率 ≥70% · 评价数 ≥100（`recommend_min_rate` /
  `recommend_min_count`，出厂默认可配置）。权重可用 `picks_weights` 配置覆盖，
  ⚠️ **表里不许出现「史低类型」项**（有单测锁定）。
  「间隔」：平史低 = 距上次同价（ITAD storelow），新史低 = 距上次史低期
  （自有记忆 `low_period.prev`，见 [pipeline.md](pipeline.md)）；记忆未建立时无值
  → 该项不计分。冷启动阶段新史低卡间隔大面积为空属预期，随史低期轮转渐进补齐。
  两处语义不同：板块是「今天有什么新史低」的榜单（名气优先，见下节），
  大卡是「今日最值」门面位（折扣优先），故拆成两套权重档
  （板块公式 `recommend_weights`，均为 `report._resolve_weights` 单一解析出处）。
- **形态**：白底；封面 3:4（三档统一，避免断点跳）；左上排名徽章；底部署低类型色条
  （新红 / 平灰）；信息三排 = ① 标题 ② 史低类型徽章 + 折扣% **右贴 Steam 图标**
  ③ 划线原价 + 现价 **右贴小黑盒图标**。
- **前端翻页 = 一页一排**（2026-10-07 定稿，手机只出一排让板块区进首屏）：
  一排几张随断点自适应（手机 2、平板/PC 最多 5，上限经 payload `pick_page` 下发）；
  只有一页时翻页控件整块隐藏。
- **取数张数**（后端 `pick_top`，口径唯一出处 `report.HOME_PICKS_PAGE`）：
  每页固定 **5 张**，总张数 = `min(新史低能凑满的整数页 × 5, home_picks)`
  （上限默认 **15**），**最低一页 5 张**——末页由平史低**补满当前页**，
  新史低凑不满时按整数页回落（10 / 5），**绝不拿平史低硬凑上限**。
  大促与日常自动适配（大促 15 张、平时通常 5 张），上限想改就改
  `home_picks`（5 的整数倍：10 / 15）。

## 行列表（四板块 / 板块完整列表）

- **板块口径 = 性质全量**（2026-10-10）：首页四板块、板块完整列表分片、agg 预聚合计数
  表共用同一份成员判据（板块 match + 在期内），**不带任何「近 N 天」窗口** ——
  日期收窄只由用户在筛选抽屉里选（前端 `dateOk` 现切）。分片若预筛窗口，
  板块页「日期=全部」会失效、agg 各档计数缩水（cb95120 回归，见 CHANGELOG）。
  仍在用「近 N 天」口径的只剩顶部大卡候选池（见上节）。
- **板块排序各走各的语义**（`report._section_sort`）：
  新史低 = 推荐公式（名气优先）· 即将到期 = 到期近 → 远 ·
  热门游戏 = **评价数降序**（平手比好评率）· 大额折扣 = **折扣降序**（平手比评价数）。
  后两者的排序选项在筛选面板「隐含置灰」（implied 表 `sort.cut` / `sort.big_cut`）。
- **板块栏位数动态**：四板块统一 `clamp(最小池量, home_section_preview_min=5,
  home_section_preview=10)`；池子不足时**如实显示池量、不凑数**。
- 一行一卡：**左侧史低类型色条（6px）** + 封面 + 中英名 + 评价·剩余天数 + 两枚商店图标
  （Steam → 小黑盒）+ 力度条 + 折扣% + 价格。
- **两种内部结构按「行自身宽度」选**（容器查询 `@container row`，不是视口断点）：
  窄行走两行、宽行走一行；力度条按行宽自适应、`--cut-bar-max` 封顶。
- **点行展开详情**（手风琴）：左栏「上次新史低 / 折扣结束」，右栏「跨区比价」；
  无比价数据时右栏写一行说明（不回落单栏）。**比价现查只覆盖「当日新增 + 即将到期」**，
  其余历史条目为估算（口径见 [../CONTEXT.md](../CONTEXT.md)「现查与估算的分工」）。
- **点大卡 → 跳「新史低」板块 + 自动定位并展开那一行**：大卡点击记下 `game_id`，
  落地后按 `.row[data-gid]` 命中就滚动 + 展开；还没渲染到就**一次加载到位**再定位
  （分片有缓存，代价有限）。
- 缺详情的行显示「**详情待补**」，不影响浏览，下次运行自动补上。
- **好评率 / 剩余天数分档上色**（服务端 `report.rate_tier` / `days_tier`），前端只拼 span。

### 板块完整列表的数据：按板块顺序分片

- 板块完整列表（点「查看更多」进去那张页）的数据是 `all/<板块>_<片号>.js`，
  每片 200 条（`ALL_SHARD_SIZE`），由 `report.write_all_shards` 产出。
- **按板块各自顺序切片**：池顺序（tier 分组 + 折扣降序）跟板块排序不相关
  （试过共享池分片，实测「热门游戏」前 30 条散落在 18 个分片里，等于没优化）。
  代价是卡片在板块间重复存储（发布体积 5.8MB → 13.1MB raw），属可重建产物，认了。
- **顺序 = 分片的物理顺序**（片号 0,1,2… 依次读出来就是板块顺序），服务端不再
  单独下发 `section_order`；排序口径仍然只有服务端一份（`report._section_sort`）。
- **第 0 片额外带** `total` / `shards` / `size` / `agg`：
  - `agg` = 构建期算好的**预聚合计数表**（5 个板块 × 160 个筛选组合的精确条数，约 4KB raw）
    ⇒ **只加载第 0 片也能显示精确的「共 N 条」**，筛选不必退化成全量加载。
  - ⚠️ `agg` 的判据必须与 app.js 的 `dateOk` / `filterOk` / `liveOk` 同一口径，
    且 `report.filter_dim_values` 与 `report.filter_specs` 的选项必须逐项一致（有单测锁）。
- 前端：`window.ALL_S["<板块>_<片号>"]` + `loadShard()`，仍是**动态 `<script>`** 而不是
  fetch（`file://` 直开要能用）；按已加载部分的命中率外推再取几片，`SHARD_CONCURRENCY = 4`。
- **换「折扣 / 价格 / 好评」排序 = 全局重排**，必须拿到该板块全部分片 ⇒ 并发全取
  （属次要路径）。
- **首页空闲预取**：`requestIdleCallback` 串行偷跑五个板块的第 0 片（≈100KB）；
  用户已经进了某个板块就立刻停手。
- ✅ **实测**（线上 7276 张卡片）：首片 gzip 各板块 ≈ 18~22KB —— **对比单文件全量降幅 97%**；
  构建 0.5s。
- ⚠️ 发布时 `output/all/` 会先被清空再写（池量每天变，防昨天的旧分片一起发布）。

## 视觉规范（决策层；具体值以 `app.css` 变量为准）

- **颜色语义（一个色相只干一件事）**：红 = 价格上的好消息（新史低色条 / 现价**同号**）、
  深一档红 = 比价「贵」；绿 = 折扣力度（条与百分比同色）；蓝 = 主色 / 好评率
  （**单蓝号**，≥90 只加粗）；粉 = 「今天结束」（粉底 + 白字）；
  琥珀 = 警示（剩余天数紧迫 / 口碑偏低）。⚠️ **别让「新史低」变绿**（会跟「折扣力度」串味）。
- **字号 6 档**（`--fs-aux/sub/body/price/title/brand`）、**间距 5 档**（`--sp-1..5`）；
  容器 max-width **1200px**、留白 `clamp(12px,4vw,56px)`。
- **断点三档**：手机 ≤`mobile_breakpoint_px` / 平板 ≤`tablet_breakpoint_px` / PC
  （经 `payload.list` 下发；**改值必须同步 CSS `@media`**，有机械校验断言）。
- **空状态**三态（无内容 / 加载中 / 加载失败）用**自绘内联 SVG**（不引图片文件），
  配色用站点现有色；失败态带「重试」按钮。

## 双端适配

- **不做 UA 判断**，一套响应式 CSS（UA 已不可靠：iPad 报 macOS、浏览器有「桌面版」开关；
  而 UA 判错的后果是布局崩，`@media` 不会错）。
- 手机上：导航收成汉堡、筛选按钮进右下浮层、精简/返回顶部做成浮动按钮
  （返回顶部滚动 >400px 才出现）。
- **精简模式**（`body.compact`）：封面隐藏、中英名同行、间距收紧、力度条下移一行；
  状态存 `localStorage`（初始化只应用不回写）。
- 移动端贴合安卓习惯：不做右上角小 × 按钮。

## 其他

- **PWA：不做**（明确砍掉）；**搜索引擎收录：无所谓**，不加 noindex。
- 页脚：链接 + 一句话说明 + 免责，**居中**；**不含生成时间 / 最近运行时间**
  （那些在顶栏与 about 页）。
